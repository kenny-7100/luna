# 工作期间持续观察与理解

## 目标与状态

用户明确要求覆盖整个工作期间，及时理解实际工作。Codex 负责理解与判断，Luna 提供观察工具、短期上下文与长期知识；不另建模型推理内核。

本文是待实施方案。目前未启动观察器，未采集桌面、截图或工作事件，当前对话也未验证可以自动接收外部事件。

## 最小数据路径

工作变化 → 本机采集与去重 → 本地事件缓冲 → 触发 Codex 读取增量 → 更新当前工作理解 → 按授权协助。

采集器只获取、规整和缓冲事实，不负责语义推理。全工作期间覆盖不等于每帧调用模型；持续采集变化，按重要事件和短时间合并触发理解。采集延迟、等待处理时间与模型处理时间分别记录。

## 先接入的信号

| 信号 | 用途与边界 |
| --- | --- |
| 前台应用、窗口、切换时间、锁屏及空闲状态 | 知道当前工作表面和覆盖是否中断；窗口标题本身不足以判断工作意图 |
| 当前浏览器页面 URL/标题与按需页面内容 | 关联 PR、Linear 任务、文档和站点；具体浏览器接入需验证 |
| VS Code 当前项目、文件与必要的诊断信息 | 定位代码工作；优先通过结构化接口获取，不能假设所有编辑器状态都已开放 |
| 按变化采样的截图和可访问性文本 | 补足 TG、弹窗、终端等 UI 上下文；实际读取能力与系统权限逐项验证 |
| GitHub、Linear 等平台的事件或查询结果 | 补充当前页面之外的任务状态，不能直接等同于用户当前意图 |

首个原型先打通前台应用/窗口与必要视觉上下文，再根据漏掉的实际信息补浏览器或编辑器适配。仅靠应用名和窗口标题不能宣称已实现工作理解。

## 理解结果

保持简短的当前工作记录：正在做什么、关联项目/任务、近期关键变化、可能的阻塞、证据及时间、哪些是推测、观察缺口。切换应用不自动代表切换任务；长时间停留也不自动代表遇到困难。

区分采集正常、等待理解、理解完成与覆盖缺口。锁屏、休眠、权限失效、采集器停止或模型不可用应显式留下缺口，恢复后标识补处理的数据，不能称为实时理解。

## 接入 Codex

- MCP 可提供“当前状态”“某时间后的增量”“按需截图”等读取工具；提供工具本身不等于自动唤醒 Agent。
- 官方 App Server 提供会话与 turn 的程序化接口，是事件触发 Codex 的候选接入方式。它仍使用 Codex；无需自行实现模型调用和推理循环。
- 验证本机版本、登录、工具权限、目标会话与串行处理方式。不能假设可直接向当前桌面对话注入事件或继承它的所有连接器。
- 先做一条工作事件触发一次 Codex 理解的实验，再确定全天接入。不预建复杂调度系统；若当前环境只能定时运行，明确它只达到周期理解。

官方资料（2026-11-11 查阅，具体本机能力未验证）：[MCP](https://developers.openai.com/codex/extend/mcp)、[App Server](https://developers.openai.com/codex/app-server)。

## 开销与数据管理

建议先以本机工作时段的变化触发加短窗口合并进行实验；窗口稳定时降低截图频率，明确新事件优先，避免旧事件无限积压。具体时延、资源和存储上限由原型测量后确定。

原始事件、窗口内容和截图放在 Git 忽略的 `.local/`，配置短期保留与清理，不随自动 push 上传。只将提炼后的必要经验写入文档；不采集全局键盘输入或剪贴板作为默认数据源。提供暂停、恢复、状态、排除应用和删除本地记录的简单入口。

## 第一阶段验收

选择一段真实工作过程，至少经历浏览器、编辑器、聊天之间的切换；Codex 应能根据证据持续更新工作理解，用户不必逐次解释。比较实际工作与推断，核对延迟、漏采、错误关联、资源开销和恢复行为。先对照验证准确度，再扩大观察范围和主动处理能力。

优先级与运行边界来自用户需求；信号选择、接入方式和验收步骤为本次建议，尚未实现或实测。
