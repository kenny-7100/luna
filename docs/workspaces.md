# 任务工作区

创建 `workspaces/<清晰任务名>/`，例如 `workspaces/github-review-helper/`。当前按手工创建与助手操作管理；尚无创建命令。

```text
<任务名>/
  TASK.md           目标、范围、验收条件、关联链接、授权范围
  STATUS.md         当前进度、已验证结果、阻塞、下一步与恢复命令
  notes.md          按需保存的研究、临时思路
  artifacts/        按需生成的交付物
  repos/            按需放置 checkout / worktree
```

只创建实际需要的文件与目录。简单任务可合并为一个 `TASK.md`；需跨会话继续的任务至少保留目标、当前状态和下一步。

## 执行与恢复

开始时阅读相关项目本身的 `AGENTS.md`，检查工作树状态，不覆盖已有改动。任务文档记录对应仓库、分支及 worktree 路径。工作区用于文件隔离，不提供进程或权限沙箱。

状态说明区分待做、进行中、阻塞与完成；保存足够的命令、产物路径、验证结果及下一步，让下一次会话可以继续。对已获授权的动作记录范围，不要求用户重复授权。

结束时核对验收条件，必要结论迁入 `docs/`，通用工具迁入 `src/luna/`。工作区整体默认被 Git 忽略，重要记录需要显式迁入受版本管理的文档；未获授权不自动清理、删除 checkout 或交付物。
