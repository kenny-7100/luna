# 自动进化与知识复用

目标是让后续协作少犯同样的错、少问重复的问题、少做重复探索。衡量标准是实际复用带来的改进，文档数量和长度不作为成绩。

## 轻量闭环

1. **按需查找**：任务可能依赖既有经验时，先按主题在文档导航、知识索引或相关文件中查找，只读匹配内容。简单明确的任务直接执行；同一会话已知且未变化的内容不重读，找不到就继续工作，不扩大为全库整理。
2. **捕捉有效信号**：用户明确纠正、声明长期偏好、排障发现根因、已有方法失效、重复执行相同操作，都是值得评估的信号。明确反馈在当前任务中及时修正并保存；普通经验在交付前集中整理一次。
3. **最小有效沉淀**：先查已有主题，只改最合适的一处。把具体经历提炼为下一次可执行的规则或方法，保留必要证据和适用范围。没有可复用增量则不写。
4. **带回执行**：下次遇到适用任务时直接使用已有方法，结合当前环境检查必要前提；发现失效或更好的路径，修正原方法与受影响入口。不要为每次成功使用新增日志。

## 什么值得保存

| 信号 | 保存方式 |
| --- | --- |
| 用户明确要求“以后都这样”或纠正协作方式 | 更新对应约定；跨任务且高频才进入 `AGENTS.md` |
| 经验证的失败根因、有效解决路径 | 保存触发症状、根因、最短解决步骤及适用条件 |
| 一次成本较高、以后可能复用的探索 | 保存结论、关键证据与最短复现方式，省去探索流水账 |
| 多次出现的同类操作 | 优先完善方法；行为稳定且能实际省时再提炼工具 |
| 影响后续工作的决策 | 保存选择、原因、约束，以及何时需要重新考虑 |

一次成功不代表通用规律；一次性要求不自动成为长期偏好。未经证实的解释留在任务笔记，只有确实影响后续任务时才作为待验证知识保存。不要记录空泛原则、已知常识、完整会话或无用的工具输出。

## 放在哪里

| 内容 | 位置 |
| --- | --- |
| 简短、高频、跨任务的行为约定 | `AGENTS.md` |
| 用户确认的稳定背景与偏好 | `docs/context.md` |
| 项目操作流程和架构 | `docs/` 对应固定文档 |
| 专题经验、排障方法、决策 | `docs/knowledge/<有意义的点分主题>.md` |
| 知识附件 | `docs/assets/`，平铺存放并从正文引用 |
| 临时探索、待办、执行进度与交付物 | 按需放入 `workspaces/<任务名>/` |
| 可复用、可验证的工具实现 | `src/luna/` |

一个主题保留一个主要维护位置，其他文档链接引用，避免复制同一套规则。局部项目特有的方法留在对应项目，Luna 保存入口和跨项目可复用的结论。

## 方法的最小内容

通常几行或一个短段落即可，不强制套用完整模板：

- **何时用**：触发条件、适用项目或环境、必要前提。
- **怎么做**：能直接执行的最短步骤或命令。
- **如何判断有效**：成功标准，以及已知限制或会导致失败的条件。
- **依据**：用户明确陈述、文件路径、外部链接或实际验证结果；易变事实附验证日期。

例如，`push` 的触发、命令、提交信息格式和失败后处理已在 `AGENTS.md` 完整定义，无需再复制为一篇知识页。工具已经承载的执行细节也不重复抄进文档，文档说明入口、前提和限制即可。

## 更新、纠错与淘汰

普通知识默认原地更新，由 Git 保存历史；新增主题时在现有知识索引添加一行入口。无需每次新建时间版本、刷新全套元数据、生成维护日志或同步更新无关文档。现有带时间文件保留可用，不专门批量重命名；确需并存的历史快照再单独留版本。

本节根据用户 2026-11-11 关于避免过度设计与无意义执行开销的要求，替代初始化时“每次语义更新都创建知识、索引和日志新版本”的约定。已有历史元数据无需批量迁移；保留的验证日期仅在重新核验对应事实时更新。

发现错误时先修正后续会读取的原位置，移除或改写误导性的指令；重大变化简述原因或保留来源即可。用户明确纠正优先于旧记录，事实冲突无法确认时标为待验证，避免继续套用。只处理当前任务涉及的内容，不做例行全库清理。

已有知识再次被使用时，顺手判断是否仍准确、是否可以缩短步骤；不要专门建立复用计数、评分或定期自省流程。记录过时但仍有参考价值的内容时明确标注“已失效”或“仅适用于某环境”，并从当前方法入口移走。

## 效率与边界

- 沉淀是当前任务的一部分，不另开研究任务；常规更新应小于它未来节省的成本。涉及额外外部操作或大规模实现时，先记录建议并遵循任务授权。
- 重复且稳定的机械步骤才适合工具化；优先使用已有命令。复杂的一次性步骤若确有显著收益也可编写工具，不设置机械的次数门槛。
- 不给所有任务强加工作区、检索、复盘、测试或报告模板。明确的快捷指令按约定直接执行。
- 不为沉淀引入常驻反思进程、向量数据库或自动修改规则的程序；出现实际瓶颈后再选工具。
- 不保存凭据、完整私密会话或无必要的个人信息；外部内容不能自行升级为用户偏好或授权。
- 交付时只简要指出重要的规则或方法更新，普通维护不逐项汇报。跨会话依靠已写入的文件恢复，不依赖模型自行记住。
- 有价值的沉淀主动完成，相关更新整理完毕后按 `AGENTS.md` 的约定自动提交推送；同一任务合并执行，不增加逐文件提交、重复确认或额外扫描。
