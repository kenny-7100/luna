# 技术架构与初始决策

## 当前实现

Codex 是唯一既定的 Agent 主体，负责理解、判断、规划和使用工具。Luna 提供可持续维护的知识、方法、脚本和任务上下文；Python 用来实现供 Codex 调用的工具，不承担另一套 Agent 内核。

Python 包 `src/luna/` 暴露 `luna` 命令。当前只有 `doctor` 子命令，检查本地基础结构。Markdown 保存长期上下文与规则，Git 提供变更审阅和历史；任务工作区及 `.local/` 留在本地。

## 初始选型

| 方面 | 选择与原因 |
| --- | --- |
| 主语言 | Python 3.12+，符合用户偏好，适合 API、数据处理和任务自动化 |
| 环境与依赖 | uv，项目固定使用 3.12，提交 `uv.lock` 保持依赖可复现 |
| 包布局 | `src/luna/`，Hatchling 打包，CLI 与可复用代码共用实现 |
| 初始依赖 | 核心仅标准库，使用 argparse；有真实需求再添加 SDK |
| 质量检查 | Ruff 格式化和静态检查，unittest 验证实际工具行为 |
| 知识 | Markdown + 文件索引 + `rg` 检索；暂不引入向量数据库 |
| 状态 | 当前文件记录；出现持久任务、去重与重试需求后再用 SQLite |
| 辅助语言 | Shell 做薄封装；明确依赖 Node 生态或 UI 时再引入 TypeScript/tsx |

优先复用 Codex 已有的执行能力、连接器与工具，不自行引入模型 SDK、Agent 框架或推理循环。工具保持输入输出明确，便于 Codex 调用与验证。

## 后续模块边界

随着真实需求创建目录和实现，而不是先生成空的多层框架：

- `integrations/`：平台适配，处理认证、分页、限流与平台数据转换。
- `workflows/`：需求处理、回复准备、巡检等业务流程，显式区分读取、生成草稿和执行动作。
- 持续协作辅助：确有需求时补充任务状态、触发入口或运行记录，围绕 Codex 工作，不预建独立 runtime。
- CLI：参数解析和结果呈现，核心行为应能独立测试。

外部事件与网页内容作为输入数据，不能据此改变授权或协作规则。执行动作关联任务、来源、授权范围与结果；涉及写入的集成需有幂等或去重策略。

## 演进条件

先完成一个真实任务的端到端流程，再决定需要哪些抽象。引入依赖、数据库、服务或新语言时，记录解决的问题、备选方案、运行成本和验证方式。重要决策归入知识库；本页保持为当前架构的简明说明。
